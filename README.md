# generating_documents

Конвейер извлечения данных из белорусских судебных/третейских документов
и формирования итоговых документов (определение о возбуждении и решение)
для постоянно действующего третейского суда.

На входе — комплект документов по делу (договор займа, исковое заявление,
претензия, свидетельство СОЗ, чек, форма «ввод данных»). На выходе —
`documents.zip` с заполненными `opredelenie.docx` и `reshenie.docx`.

Конвейер был портирован с n8n-воркфлоу на чистый Python. **Все значения
извлекаются детерминированно (regex/правила), без LLM** — входные документы
это машинно-сгенерированные шаблоны сервиса «Капуста» с устойчивыми подписями
полей и форматами дат/чисел.

## Стек

- Python 3.11, Flask
- pymorphy3 — склонение ФИО
- python-docx — заполнение шаблонов
- easyocr / PyPDF2 / pdf2image — конвертация входов в текст
- Docker Compose (Flask-сервис + nginx-фронт)

Внешних API и сетевых вызовов в конвейере нет; кредов/ключей не требуется.

## Быстрый старт

```bash
docker compose up -d --build
```

UI на http://localhost:8089 (внутри контейнера Flask на :8000, маппинг 8089→8000).
Nginx-фронт на 56783.

## Архитектура

Поток (порядок выполнения в `pipeline.py`):

1. **Чтение входов** — `out_txt/*.txt`: загруженные пользователем документы,
   уже сконвертированные в текст (PDF/DOCX → TXT делает `uploading_documents.py`).
2. **Склейка + нормализация** — все тексты в одну строку с заголовками
   `==== имя_файла ====`, склеиваются переносы, выделяются разделы.
3. **Извлечение полей ручного ввода** — `extract_vvod_dannyh()` парсит
   `vvod_dannyh.txt` (генерируется `data_entry.py`) построчно «Метка: значение»:
   город, судья, суд, номера/даты дела, реквизиты заседания.
4. **Извлечение полей из документов** — `extract_documents()` тянет по
   фиксированным фразам шаблонов: ФИО сторон (для склонений), номер/дата/срок/
   ставку займа, первую строку графика платежей (дата/сумма/осн. долг/проценты),
   суммы из искового (основной долг, проценты, неустойка).
   Извлекаются только поля, которые реально подставляются в `opredelenie.docx` /
   `reshenie.docx`; неиспользуемые (email, ИНН, паспорт, способ погашения и т.п.)
   не ищутся.
5. **Извлечение из Свидетельства СОЗ** — `extract_from_certificate()`: адреса
   сторон, `LOANDATE_START`, `LOAN_AMOUNT` по строгим регуляркам.
6. **Извлечение по строгим маркерам** — `extract_strict_markers()`:
   `PRETENSION_DATE`, `PENALTY_TO` (период пеней по контексту).
7. **Нормализация** — ФИО, адреса, паспорта приводятся к каноническому
   регистру (`normalize_name`, `normalize_address`, `normalize_passport`);
   правка регистра адресных меток («Место Регистрации:» → «место регистрации:»).
8. **Вычисление формул** — `compute_formulas()`: `PRINCIPAL_SUM` (формат BYN),
   `TOTAL_SUM`, `INTEREST_FROM/TO`, `PENALTY_FROM` (`LOANDATE_END`+1),
   `JUDGE_INITIALS`, `JUDGE_POSITION_WITH_DASH`, префикс `CITY`.
9. **Морфология ФИО** (`morph_fio.py`) — pymorphy3 склоняет ФИО по падежам
   и дописывает `*_GENT`, `*_DAT`, `*_ABLT` ключи.
10. **Подстановка в шаблоны** (`documents.py`) — берёт docx-шаблоны и пишет
    результат в `out_docs/`, упаковывает в `documents.zip`.

Поле, не найденное регуляркой, просто не попадает в результат (прогон не
падает) — `documents.py` подставит пробел вместо отсутствующего ключа.

## HTTP-эндпоинты (`app.py`)

| Метод | Путь | Что делает |
|---|---|---|
| GET  | `/` | UI |
| POST | `/generate-txt` | Сохраняет форму «ввод данных» в `out_txt/vvod_dannyh.txt` |
| POST | `/convert-and-send` | Принимает файлы, конвертирует в txt в `out_txt/` |
| POST | `/upload` | Принимает уже готовые txt в `out_txt/` |
| POST | `/run-n8n` | Запускает конвейер (`run_pipeline()`) → `out_txt.json` |
| POST | `/morph-fio` | Дополняет `out_txt.json` склонёнными ФИО |
| GET  | `/get-placeholders` | Отдаёт текущий `out_txt.json` |
| POST | `/generate-docs` | Подставляет плейсхолдеры → `out_docs/documents.zip` |
| GET  | `/download-docs` | Скачивает zip и чистит рабочие папки |
| POST | `/pack-zip` | Архивирует `out_txt/` |
| GET  | `/logs` | Страница сквозных логов событий приложения (`app_events.jsonl`) |
| POST | `/logs/clear` | Очищает лог событий |
| GET  | `/runs` | Детализация прогонов конвейера по шагам (`runs.jsonl`) |

Типовой пользовательский поток: загрузить документы → `/convert-and-send` →
заполнить форму → `/generate-txt` → `/run-n8n` → `/morph-fio` →
`/generate-docs` → `/download-docs`.

## Логи

- **`app_events.jsonl`** — сквозной лог всех событий приложения и ошибок
  (запросы/ответы, доменные события: конвертация, конвейер, склонения, генерация,
  очистка; необработанные исключения пишутся с трейсбэком). Дублируется в stdout
  (виден в `docker compose logs`), ротируется до последних 1000 строк. Просмотр —
  страница **`/logs`** (новые сверху), очистка — кнопка на ней.
- **`runs.jsonl`** — пошаговый журнал прогонов `run_pipeline()`: время старта,
  номер за день, успех, суммарное время и `steps` (имя шага, время, инфа, ошибка).
  Ротируется до последних 25 записей. Детальный просмотр — страница **`/runs`**.

## Настройки (`.env`)

Параметры приложения задаются переменными окружения в `.env`:

- `PROCESSING_DELAY_SECONDS` — искусственная задержка этапа обработки документов
  на фронтенде. Впишите число секунд (0 — без задержки). Значение читается при
  старте контейнера, поэтому после правки выполните `docker compose up -d`
  (пересоздание контейнера; `restart` недостаточно — `.env` перечитывается на `up`).

## Структура проекта

```
pipeline.py            # ядро конвейера (извлечение кодом, формулы)
app.py                 # Flask: HTTP-роуты, хуки логирования
config.py              # чтение настроек из переменных окружения (.env)
app_log.py             # сквозное логирование событий/ошибок
data_entry.py          # сохранение формы → vvod_dannyh.txt
uploading_documents.py # конвертация PDF/DOCX → TXT (OCR на easyocr)
morph_fio.py           # склонение ФИО (pytrovich) + должности судьи (pymorphy3)
documents.py           # подстановка плейсхолдеров в шаблоны docx
placeholders_api.py    # CRUD-роуты для редактирования placeholders
utils.py               # упаковка out_txt в zip
templates/index.html   # фронт
out_txt/               # рабочее: входы + out_txt.json (gitignored)
out_docs/              # рабочее: готовые docx + documents.zip (gitignored)
app_events.jsonl       # сквозной лог событий (страница /logs)
runs.jsonl             # лог прогонов конвейера (страница /runs)
n8n.json               # исходный n8n-воркфлоу (историческая справка)
```

## Контракт плейсхолдеров

Результат — словарь `{"{{KEY}}": "value", ...}` в `out_txt/out_txt.json`.
Имена ключей фиксированы в экстракторах `pipeline.py`; формульные ключи
(`PRINCIPAL_SUM`, `TOTAL_SUM`, `JUDGE_INITIALS`, `PERIOD_END`,
`JUDGE_POSITION_WITH_DASH`) вычисляются в `compute_formulas()`.

## Известные ограничения

- **PDF читается только текстовый слой** (PyPDF2); сканы — через easyocr
  (медленно).
- **Экстракторы заточены под шаблоны сервиса «Капуста».** Документы другой
  структуры (другие подписи полей) потребуют доработки регулярок.
- **Морфология фамилий** — pymorphy3 иногда склоняет нестандартные фамилии
  типа «Кузьма», «Лобанок» неправильно; ручная коррекция не реализована.
- **Род глагола «обратился/обратилась»** в шаблонах зашит мужским — для
  истца-женщины нужна правка шаблона или ветвление.
